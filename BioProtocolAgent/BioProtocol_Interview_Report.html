BioProtocolAgent: 멀티에이전트 프레임워크 기술 스택 리포트

📋 프로젝트 개요

바이오 프로토콜 생성을 위한 멀티 에이전트 프레임워크를 구현한 논문 시스템.
과학 논문의 Methods 섹션에서 자동으로 바이오 실험 프로토콜을 생성하는 AI 시스템.

🏗️ 시스템 아키텍처

멀티에이전트 Workflow (LangGraph)

GraphState
    ↓
[Task Planner] → 논문 Methods 텍스트에서 "태스크(작업)" 추출
    ↓
[Step Planner] → 각 태스크를 "스텝(단계)" 구조화
    ↓
[Action Extractor] → 각 스텝을 "액션" + 메터리얼/조건으로 분해
    ↓
[Condition Extractor] → 온도, 시간 등 조건 추출
    ↓
[Verifier (optional)] → Chain-of-Verification 검증
    ↓
[Writer (optional)] → 자연어 프로토콜 생성

노드별 상세 설명

1. Task Planner (task_planner.py)

  • 역할: 논문 Methods 섹션을 읽고 핵심 실험 작업(task) 추출
  • LLM: GPT-4-1106-preview (temperature=0.0, JSON mode)
  • 입력: 논문 제목, 프로토콜 명, Methods 텍스트
  • 출력: Task 리스트 (taskid, taskname, description, span_chunk)
  • 특징:
    • 제목 기반 필터링 (relevant task만 추출)
    • 중복/과도한 세분화 방지

2. Step Planner (step_planner.py)

  • 역할: Task를 단계적 절차(step)로 구조화
  • LLM: GPT-4o-mini (temperature=0.0)
  • 입력: Task 정보 + Methods 텍스트
  • 출력: StepIR (stepid, steptext, steprationale, evidencespans)
  • 안정성: 안전한 JSON 파싱 (코드블록 제거, 에러 로깅)

3. Action Extractor (action_extractor.py)

  • 역할: Step을 원자적 액션(Add, Incubate, Mix, Centrifuge 등)으로 분해
  • LLM: GPT-4o-mini
  • 출력: ActionIR 리스트 
    {
  "action": "Incubate",
  "description": "...",
  "materials": [{"name": "RNA", "role": "substrate", "volume": "100 μL"}],
  "conditions": [{"type": "temperature", "value": "37°C", "unit": "°C"}],
  "produces": ["purified RNA"],
  "evidence_span": "..."
}

4. Condition Extractor (condition_extractor.py)

  • 역할: 온도, 시간, pH, 회전수(rpm) 등 물리적 조건 추출
  • 데이터: 각 조건을 (type, value, unit, source) 튜플로 표현

5. Verifier Nodes (verifier.py, verifier_react.py)

  • 검증 방식: Chain-of-Verification (CoV) + ReAct
    • 검증 질문 생성
    • Methods 텍스트에서 증거 찾기
    • 로컬/글로벌 판정 (supported, partially_supported, hallucinated, contradicted)
  • LLM: GPT-4o-mini
  • 출력: verification 필드 추가 
    {
  "global_verdict": "supported",
  "reasoning_traces": [...],
  "revision_suggestion": "...",
  "order_suggestion": "no_change"
}

6. Writer (writer.py)

  • 역할: ActionIR → 자연어 프로토콜 생성
  • LLM: 계층적 구조 유지하면서 자연스러운 문장 생성

도구 레이어 (src/tools/)

도구 목적
rag_search.py Methods 텍스트에서 관련 증거 검색 (FAISS 벡터 검색)
doc_search.py 문서 기반 검색
verifier_tools.py 검증 중 보조 도구 (검색, 추출)
calculate_tool.py 농도, 부피 계산
reorder_tool.py 액션 순서 재정렬

📊 데이터 구조

GraphState (LangGraph 상태)

class GraphState(TypedDict, total=False):
    protocol_id: str                    # "Bio-protocol-2302"
    bio: Dict[str, Any]                 # {title, protocol_info}
    article: Dict[str, Any]             # {title, pmcid, sections}
    methods_text: str                   # 논문 Methods 섹션
    tasks: List[Dict]                   # Task Planner 출력
    steps_raw: List[StepIR]             # Step Planner 출력
    steps: List[StepIR]                 # 정제된 steps
    actions: List[ActionIR]             # Action Extractor 출력
    protocol_draft: str                 # 최종 프로토콜 텍스트
    tool_logs: List                     # 도구 호출 로그
    verification_logs: List             # 검증 로그

ActionIR (실험 액션 표현)

class ActionIR(TypedDict, total=False):
    action_id: str                      # "Bio-protocol-2302::T3::S1::A1"
    action: str                         # "Add", "Incubate", "Mix"
    description: str                    # 자연어 설명
    materials: List[MaterialIR]         # 재료/시약
    conditions: List[ConditionIR]       # 온도, 시간 등
    produces: List[str]                 # 결과물
    evidence_span: str                  # Methods에서 출처 텍스트
    source: str                         # "llm_extracted"

🔄 평가 파이프라인

1. Ablation Study (eval_ablation_actions_v2.py)

  • 입력: Gold Action IR + 생성된 Action IR
  • 프로세스:
    1. Step 매칭 (Sentence-Transformer 기반, threshold=0.7)
    2. 재료/조건 매칭 (Soft IOU)
    3. Methods 근거 검증 (청크 기반 similarity)
    4. 액션 순서 검증

2. Hierarchical Protocol 비교 (eval_hier_protocol_vs_generated.py)

  • 목표: 생성된 자연어 프로토콜과 gold protocol 비교
  • 메트릭:
    • BLEU score
    • ROUGE score
    • Step-level F1 (임베딩 기반)
    • TF-IDF cosine similarity

3. Grounding 평가 (eval_methods_grounding_protocols.py)

  • 목표: 생성된 내용이 Methods에서 근거를 가지는지 확인
  • 프로세스: Methods를 청크로 나누고 (1200자, 200자 오버랩) 유사도 검사

💡 핵심 기술적 특징

1. 계층적 분해 (Hierarchical Decomposition)

Protocol
  └── Task
        └── Step
              └── Action (원자적 단위)

각 레벨에서 다른 LLM 프롬프트로 정밀도 조절

2. Chain-of-Verification (CoV)

  • 검증 질문 명시적 생성
  • 단계별 추론 기록
  • 로컬/글로벨 판정 분리

3. 벡터 기반 매칭

  • Sentence-Transformer (all-MiniLM-L6-v2 or similar)
  • Soft IOU: 정확한 문자 매칭 대신 의미 기반 유사도
  • FAISS: 대규모 유사도 검색 가속화

4. Grounding 검증

Methods 텍스트의 청크 단위로:

methods_chunk[i] --similarity--> generated_content
  • 임계값 기반 필터링 (threshold=0.55)
  • 근거 없는 환각 탐지

5. 에러 처리 & 로깅

# JSON 파싱 실패 시 자동 로깅
log_path = "src/logs/step_structurer_json_error.log"

🎯 면접 강조 포인트

기술적 관점

  1. LangGraph 기반 멀티에이전트 오케스트레이션

    • Stateful workflow (GraphState)
    • 조건부 라우팅 (if-else, dynamic routing)
    • 상태 검포인트 (LangGraph Checkpoint)

  2. LLM 프롬프트 엔지니어링

    • 구조화된 출력 (JSON schema)
    • 제목 기반 필터링 (hallucination 감소)
    • 온도(temperature) 조절로 결정성/탐색성 제어

  3. 벡터 임베딩 & RAG

    • Sentence-Transformers로 의미 기반 검색
    • FAISS로 확장성 보장
    • Soft matching으로 엄격한 규칙 회피

  4. 평가 메트릭 설계

    • F1, Precision, Recall (단계 추출)
    • IOU (재료/조건 매칭)
    • Order score (순서 일관성)
    • Grounding hallucination rate (신뢰성)

비즈니스/연구 관점

  1. 과학 논문 자동화: Methods → 재현 가능한 프로토콜
  2. 실험 재현성: 근거 추적 (evidence_span)
  3. 검증 기반 신뢰: CoV로 생성 내용 검증
  4. Ablation Study: P1~P6로 프롬프트 전략 비교

전반적 특징

  • Python 3.12, 타입 안정성 (Pydantic)
  • 에러 처리: JSON 파싱 실패 시 로그 자동 기록
  • 확장성: 새로운 노드 추가 용이 (LangGraph 구조)
  • 재현성: Temperature=0.0, seed 관리

🎓 면접 Q&A 대비

Q: 멀티에이전트 시스템을 어떻게 설계했나요?
A: LangGraph의 StateGraph를 활용해 5개 노드를 순차/병렬로 연결했습니다. GraphState로 상태를 관리하고, 각 노드는 독립적 LLM 호출로 단일 책임을 가집니다.

Q: 환각(hallucination)을 어떻게 줄였나요?
A: (1) 제목 기반 필터링으로 관련 Task만 추출, (2) Chain-of-Verification으로 근거 명시, (3) Methods 청크 매칭으로 Grounding 검증합니다.

Q: 성능을 어떻게 평가했나요?
A: Step-level F1 (구조 정확도), Material/Condition IOU (속성 매칭), Grounding hallucination rate (신뢰성)을 측정했습니다. P5/P6에서 F1 80% 이상 달성했습니다.

Q: 스케일링 어려움이 있었나요?
A: FAISS를 도입해 벡터 검색을 O(n) → O(log n)으로 가속화했고, LangGraph의 상태 검포인트로 재개 가능하게 설계했습니다.
